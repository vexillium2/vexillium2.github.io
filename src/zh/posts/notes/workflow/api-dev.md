## 定位

> 把 system-design 产出的 Tech Spec 与 API 契约，变成可运行、可维护、安全的代码。
> 本文件沉淀 API 开发阶段的完整 SOP，每个环节均包含 AI/Agent 增强实践。

- **输入**：Tech Spec、OpenAPI 契约、表结构设计
- **下游**：code-review（评审）、testing（测试）、deploy-mantain（部署运维）

## 一、单个 API 开发流程

### 1.1 开发 Checklist

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 读契约 | 确认输入输出、错误码与 system-design 一致 |
| 2 | 分层实现 | Controller（校验+组装）→ Service（业务+事务）→ DAO（数据访问） |
| 3 | 参数校验 | 存在性 → 格式 → 业务规则 |
| 4 | 事务边界 | 明确哪些操作必须原子，传播行为正确 |
| 5 | 错误处理 | 捕获归类、转友好提示、不泄漏堆栈 |
| 6 | 日志 | 关键入参出参、耗时、Trace ID，敏感信息脱敏 |
| 7 | 自测 | 正常 / 异常 / 边界 / 并发场景 |
| 8 | 提交 | 单测通过 + self-review + 规范 commit |

### 1.2 连接配置（环境准备）

- 注意配置写的对不对：数据库连接、Redis、消息队列、配置中心
- 本地 / 测试 / 生产环境配置分离，敏感配置走环境变量或配置中心

## 二、RESTful API 设计规范

> 参考：[RESTful API 设计指南](https://www.ruanyifeng.com/blog/2014/05/restful_api.html)

### 2.1 URL 规范

- 资源名复数、小写、使用 `-` 分隔
- 后端专属 URL 带版本：`/api/v1`
- 查询条件放 URL 而非 Request Body（可被浏览器、代理服务器和 CDN 缓存）

```text
GET /api/v1/resources?name=张三&age=25    ✅ 查询条件在 URL
GET /api/v1/projects/{projectId}/tasks    ✅ 资源层级：项目下的任务
POST /api/v1/resources/query               ❌ 非标准操作滥用
```

### 2.2 标准操作

| 方法 | 用途 | 幂等 |
|------|------|------|
| GET | 查询 | ✅ |
| POST | 创建 | ❌ |
| PUT | 全量更新 | ✅ |
| PATCH | 部分更新 | ✅ |
| DELETE | 删除 | ✅ |

### 2.3 命名规范

- 前后端统一使用驼峰（camelCase）
- 数据库使用下划线（snake_case），数据库对大小写不敏感

### 2.4 HTTP 状态码与业务错误码

- HTTP 状态码表达传输层结果：200 / 400 / 401 / 403 / 404 / 500
- 业务错误码表达业务层结果，统一返回结构：

```json
{
  "code": 10001,
  "message": "手机号格式不正确",
  "data": null
}
```

## 三、参数校验

### 3.1 三层校验

1. **Controller 层**：格式校验（JSR-380 注解 / DTO 校验）
2. **Service 层**：业务规则校验（手机号已注册、库存不足）
3. **数据库层**：约束兜底（唯一索引、非空）

### 3.2 校验项分类

- 存在性：必填参数
- 格式：JSON 结构、正则（手机号、邮箱、金额）
- 取值范围：边界、枚举
- 业务校验：依赖当前业务状态

### 3.3 错误提示

- 对用户友好，给出可执行的修正建议
- 格式统一，前端可直接展示

### 3.4 🤖 Agent 增强实践

```text
我要写一个用户注册接口，参数有：
- phone: 手机号
- password: 密码
- email: 邮箱
- code: 短信验证码

请穷举所有需要做的参数校验规则，包括：
1. 存在性校验
2. 格式校验（正则表达式）
3. 业务校验（密码强度、手机号是否已注册）
4. 安全校验（防注入、XSS）
```

## 四、事务、幂等与并发

### 4.1 事务边界

- 事务越短越好：长事务持有锁时间长，影响并发
- 注意 @Transactional 常见坑：自调用失效、异常被吞、传播行为错误

### 4.2 幂等性设计

> 异步场景（MQ 重试、用户重复提交）会导致同一操作执行多次，必须保证幂等。

- **唯一键**：业务唯一标识建唯一索引，重复插入报错后返回已成功结果
- **状态机**：只允许合法状态流转
- **Redis SETNX**：加锁 + 去重标记
- **消息消费**：消费前查已处理表，保证 at-least-once 下的最终一致

### 4.3 锁

- 乐观锁：版本号 / 时间戳，适合冲突少的读多写少
- 悲观锁：`SELECT ... FOR UPDATE`，适合冲突多的写密集

### 4.4 🤖 Agent 增强实践

```text
请 review 以下代码的幂等性与并发安全性：

[粘贴代码]

检查点：
1. 重复提交 / 重复消费是否安全
2. 并发更新是否可能丢失更新
3. 事务边界是否正确
4. 锁的粒度是否合理
```

## 五、错误处理与日志

### 5.1 错误处理

- 统一异常处理（如 Spring 的 `@RestControllerAdvice` + 全局异常捕获）
- 异常分类：参数异常 → 业务异常 → 系统异常 → 未知异常
- 外部 IO（网络、文件、数据库）调用必须处理异常，确保资源释放
- 禁止把堆栈信息返回给前端，只记录在服务端日志

### 5.2 日志规范

- 结构化日志（JSON 格式），便于检索与聚合
- 日志级别：DEBUG（开发）/ INFO（关键节点）/ WARN（可恢复问题）/ ERROR（异常）
- 每个请求携带 Trace ID，贯穿全链路

## 六、安全实现

### 6.1 认证与授权

- 认证：JWT / OAuth2 / SSO
- 授权：RBAC（角色权限）、ABAC（属性权限）
- 会话方案：JWT + Redis 缓存 Token，支持踢下线与黑名单

### 6.2 越权防护

- 水平越权：校验资源归属（如只能操作自己的订单）
- 垂直越权：校验角色权限（普通用户不能调管理员接口）

### 6.3 常见漏洞防护

- SQL 注入：参数化查询 / ORM，禁用字符串拼接
- XSS：输出转义 + CSP
- 敏感数据：HTTPS 传输、加密存储、日志脱敏
- 依赖安全：SCA 扫描（Snyk / OWASP Dependency-Check）

### 6.4 限流

- 令牌桶 / 漏桶 / 滑动窗口
- Redis INCR + EXPIRE 或 Lua 脚本保证原子性
- 分布式限流 vs 单机限流取舍

### 6.5 🤖 Agent 增强实践

```text
请对以下代码做安全审计：

[粘贴代码]

重点检查：
1. SQL 注入 / XSS / CSRF
2. 水平与垂直越权
3. 敏感数据是否加密或脱敏
4. 接口是否缺少鉴权或限流
5. 依赖版本已知漏洞
```

## 七、典型 API 类型实现

### 7.1 CRUD 类：某张表的增删改查

- 分层结构：Controller → Service → Repository
- 分页查询优化（深分页：延迟关联 / 游标）
- 批量操作、软删除

### 7.2 认证类：单点登录注册

- JWT + Redis 缓存 Token
- Token 刷新、单点登录踢下线、黑名单机制

### 7.3 限频类：签到限制多次访问

- Redis INCR + EXPIRE 或 Lua 原子脚本
- 滑动窗口统计，返回剩余次数

### 7.4 复杂业务类

- 多表事务，明确事务传播行为
- 分布式事务方案选型（2PC / TCC / Saga / 本地消息表）

## 八、性能测试与优化

### 8.1 压测

- 工具：JMeter / k6 / Locust
- 指标：QPS、P95、P99 延迟，错误率
- 关注接口 QPS 与资源占用（CPU / 内存 / 连接数）

### 8.2 SQL 与代码优化

- EXPLAIN 分析慢查询
- 避免 N+1 查询（批量查询 + 关联）
- 避免循环内调用 DB / 外部服务（合并为批量接口）
- 优化顺序：先加索引 → 再加缓存 → 最后才上 MQ / 分库

### 8.3 缓存三兄弟（穿透 / 击穿 / 雪崩）

- 穿透：布隆过滤器 / 缓存空值
- 击穿：互斥锁 / 逻辑过期
- 雪崩：随机过期时间 / 多级缓存

## 九、数据库变更 SOP（DDL）

| 阶段 | 检查项 |
|------|--------|
| 脚本编写 | 迁移脚本幂等、带版本号；同时编写回滚脚本 |
| 预发验证 | 预发环境执行成功；应用兼容新旧 schema |
| 发布执行 | 低峰期执行、先备份、先从库后主库、观察数据库负载 |
| 发布验证 | 数据完整性、应用功能正常；异常立即回滚 |
