# AI 产品经理的 SOP

> **主线**：读完能拿到一套按「产品开发流程」组织的 AI 产品经理工作 SOP——从洞察发现到上线迭代六个阶段，每个阶段都知道：先做什么后做什么（工作流）、和谁开什么会（跨部门协同）、用哪个方法/工具（skill 映射）。
>
> 状态：**大纲**（按流程拆解工作流，未展开细节）

> **全程可用**：`pm-master`（分诊 / 路由 / 编排）、`pm-advisory-board`（多视角评审）贯穿所有阶段，不单列成章。

## 阶段一：洞察与发现

*这一阶段回答：有什么值得做的真问题？*

- **工作流**：收集需求与反馈（需求池 / VOC）→ 用户调研与访谈 → 竞品拆解 → 数据与案例洞察 → 沉淀「真问题」清单
- **跨部门协同**：运营 / 销售 / 客服（反馈与工单）、数据（拉数定位）、市场（行业动态）
- **方法与工具**：`pm-survey-designer`、`pm-competitor-deconstructor`、`pm-analytics`；判断层 `pm-advisor-cagan`（机会 / 风险）、`pm-advisor-torres`（机会树）、`pm-advisor-yujun`（用户价值）、`pm-method-mom-test`（访谈去诱导）

## 阶段二：定义与设计

*这一阶段回答：怎么把问题变成一个可落地的方案？*

- **工作流**：定义「问题 + 验收标准」（区分问题 vs 方案）→ 模型选型与能力评估 → 设计 Agent 工作流 / Prompt / 工具调用 / RAG / 上下文 → 不确定性兜底与降级设计 → 成本与商业化测算 → 原型验证 → 写 PRD
- **跨部门协同**：算法（能力边界 / 可行性）、工程（技术方案 / 成本预估）、法务 / 安全（合规风险前置）、设计（原型）
- **方法与工具**：`pm-prd-writer`、`pm-image2proto`、`pm-image2pencil`、`pm-url2proto`；判断层 `pm-method-story-mapping`（切 MVP）、`pm-method-build-trap`（连回 outcome）

## 阶段三：评审与排期

*这一阶段回答：方案对不对、值不值得现在做、按什么顺序做？*

- **工作流**：评审预演 → 需求评审会 → 技术评审会 → 优先级排序（价值 ÷ 成本 ÷ 不确定性）→ 砍需求（不做会怎样）→ 路线图与排期
- **跨部门协同**：研发 / 算法（技术评审会）、设计（设计评审）、数据（数据需求评审）、法务 / 安全（合规评审）、运营（场景对齐）、排期 / 迭代规划会
- **方法与工具**：`pm-review-board`、`pm-prioritization-engine`、`pm-roadmap-planner`；判断层 `pm-advisor-cagan`（四大风险复核）

## 阶段四：开发与评测

*这一阶段回答：怎么把方案做成「质量达标」的产品？*

- **工作流**：埋点与数据体系 / 看板规划建设 → harness 搭建与调试 → 评测体系搭建（eval set / 黄金集 / badcase 库）→ evaluation 全流程 → 非确定性验收（评测集 + 阈值）→ A/B 实验设计
- **跨部门协同**：算法（模型 / harness / eval）、数据（数据体系 / 埋点落地）、工程（功能开发）、QA（验收标准对齐）
- **方法与工具**：`pm-tracking-spec-writer`、`pm-experiment-designer`

## 阶段五：上线与发布

*这一阶段回答：怎么安全地上线并推向多场景？*

- **工作流**：灰度与回滚方案 → 上线评审（go / no-go）→ 安全合规上线（内容安全 / 护栏 / AIGC 标识 / 备案）→ 线上监控与 badcase 监控 → AI 能力多场景接入落地
- **跨部门协同**：工程 / 算法（灰度 / 回滚）、法务 / 安全（合规）、运营（多场景接入 / 活动配合）、客服（客诉承接）
- **方法与工具**：复用 `pm-master` 编排 + 阶段四的监控 / 评测产物

## 阶段六：跟进与迭代

*这一阶段回答：上线后有没有达到预期，下一步改什么？*

- **工作流**：数据看板监控 → 数据分析归因 → 实验验证 → badcase 分析 → 反馈闭环（数据飞轮 → SFT / RLHF）→ 复盘 → 新问题回到阶段一
- **跨部门协同**：数据（看板 / 分析）、算法（模型迭代）、运营（运营效果复盘）、复盘会
- **方法与工具**：`pm-analytics`、`pm-experiment-designer`、`pm-postmortem-writer`；判断层 `pm-method-build-trap`（是否掉进功能陷阱）
