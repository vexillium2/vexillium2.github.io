Prompt Engineering 提示词工程

这一章写提示词工程：怎么把任务、约束、示例、输出格式"说"给模型，让它在产品里稳定产出可用的结果。先校正一个预期：提示词不是写给模型的咒语，而是写给自回归模型的条件续写信号——它调整的是输出的概率分布，不是给模型的硬命令。这个本质决定了全章的基调：提示词是软约束，凡是"必须成立"的格式与安全要求，最终都要靠结构化输出、校验和系统隔离兜底，而不是靠措辞。行文按"怎么把任务说清楚 → 怎么借示例与推理范式提升复杂任务表现 → 怎么拿到可解析的输出 → 怎么把提示词当工程管理 → 怎么面对对抗性输入"推进，各小节都会直接覆盖对应的高频面试追问点。

RAG 检索增强生成

这一章把 RAG 当作一条数据管道来讲：从"用户问了什么问题"到"模型拿到了什么证据"，再到"答案有没有钉在证据上"。模型参数里的知识是静态的、会过时的，RAG 的思路是把回答的依据从"参数记忆"挪到"可检索的外部知识库"——知识更新时改库而不是改模型。贯穿全章有一条主线：RAG 的输出质量上限由检索到的证据质量决定，模型生成只是把这份证据"如实翻译"成回答。所以数据侧（解析、切块、清洗、索引）和检索侧（改写、召回、精排）的投入，决定了一个 RAG 系统能走多远；真正工程化 RAG 的人，日常打磨的也主要是这两端，而不是模型的提示词。沿着"架构总览 → 选型 → 查询端 → 检索端 → 证据端 → 向量化与存储 → 数据处理 → 高级形态与评估"推进，各小节的面试高频点就地讲清。

Agent 智能体

这一章把 Agent 当作一套需要自己搭建的运行时系统来分析，而不是某个现成框架的说明书。模型从"单次问答"变成 Agent，核心变化不在模型本身，而在它外面多出的那个循环：模型只负责每一步做出"下一步做什么"的决策，代码负责把决策变成真实的工具调用、把结果喂回去、判断该不该停。这个结构性变化会引出本章的主题——规划以什么模式展开、任务怎么拆、跨步骤与跨会话的状态（记忆）怎么存取、要不要让多个决策者协作、人在回路放在哪个节点、上下文窗口如何在循环中被反复组装、以及这套系统独有的失败方式。面试里关于 Agent 的高频问题，就地融入对应小节回答，不单独堆"面试题"章节。

工具调用与 Tool Engineering

这一章讲模型"如何触碰真实世界"。单靠参数里的静态知识，模型既无法拿到实时数据，也无法产生真实副作用；工具调用（Function Calling / Tool Use）就是那个接口——模型不再输出纯文本，而是输出"我想调用哪个工具、用什么参数"的结构化意图，由你的代码去真正执行。本章从最底层的调用机制写到工具设计方法论，再进入围绕工具的生态协议：MCP 把工具标准化成可跨应用复用的服务，Agent Skills 把"怎么用工具做完一类事"的方法沉淀成可加载的知识，A2A 解决 Agent 与 Agent 之间的任务委派，AG-UI 类协议则统一 Agent 与前端界面的流式交互。这些协议层内容演进很快，所以行文只落架构模型、原语与选型边界，不写死具体版本结论——凡是会过时的细节，都按"该看什么维度、如何自测"处理。

Agent Harness 工程

这一章讨论模型循环外面那一圈工程外壳——Agent Harness。模型只负责"下一步做什么"的决策，可决策产生之前与之后的所有事情，都需要 harness 兜住：动作在哪执行、越权怎么办、跑到一半断电怎么恢复、上下文怎么在不失真的前提下省着用、烧钱失控了谁来踩刹车、被恶意内容诱导时最后一道闸在哪、出问题后凭什么复盘。编码类 Agent（如 Claude Code、Codex、OpenHands）是观察 harness 结构最好的样本——它们把同样的循环包装进沙箱、权限与状态体系里，差异只在取舍。凡是会随版本变化的厂商细节，一律按"该看什么维度、如何自测"处理，不写死结论。

Agent 评估

这一章把"评估"当作 Agent 研发里的一等工程来写。传统模型评估解决"这个模型行不行"，Agent 评估要回答的问题复杂得多：不只是"任务完成没有"，还有"它是哪一步开始错的、是不是用危险路径完成的、换几次采样还稳不稳、改了一次 prompt 有没有偷偷弄坏别的事"。Agent 是模型、工具、上下文组装、循环控制的组合系统，任何一层变动都可能影响整体表现，而没有评估体系的团队，每一次升级都是在盲改。本章从"为什么难"讲起，给出分层评估、LLM 裁判、benchmark 的正确用法，再落到自建评估集与 CI 化落地。凡是会随榜单与版本变化的内容，按"该看什么维度、如何自测"处理，不写死结论。
