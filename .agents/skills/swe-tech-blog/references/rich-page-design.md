# MDX / Astro 富媒体设计规则

设计图片、动效或交互时读取。正文以 MDX 写作，Astro 承载布局与组件。本文件解决表达媒介选择，不替代内容覆盖和学习性审校。

## 先做页面故事板

正文理解路径明确后，为确需特殊表达的位置记录设计目的。允许在写作时探索图稿，但不能围绕现成组件反向压缩正文：

| 字段 | 要回答的问题 |
|---|---|
| 章节目标 | 读者看完或操作后，应该新理解什么？ |
| 表达媒介 | 为什么文字不足，选择 HTML、SVG、图片、动效、视频或 3D 的理由是什么？ |
| 交互目的 | 用户的哪个动作会揭示哪个机制？没有动作就不要伪装成交互。 |
| 静态退路 | JS 未加载、动效关闭或设备性能不足时，核心信息如何仍可阅读？ |
| 复用级别 | 是全站通用组件、领域组件，还是只属于这一篇文章？ |

故事板只覆盖真正需要设计的章节。普通解释段落不必为了表格完整而添加视觉组件。

## 媒介选择阶梯

从成本最低的一层开始，只有上一层无法清楚表达时才升级：

1. **正文与代码**：概念、判断、边界和可复现行为。
2. **语义 HTML**：表格、`details`、步骤、术语卡、时间线、对比面板。
3. **静态图或 SVG**：结构、依赖、数据流、空间关系；结构图优先 SVG，便于选择文字、适配主题和无障碍描述。
4. **动画**：状态随时间变化，且逐帧变化本身包含信息。必须允许暂停并尊重 `prefers-reduced-motion`。
5. **交互组件**：参数探索、分支决策、局部模拟、可视化调试。用户操作应改变可观察结果。
6. **视频或 3D**：只有二维表达会丢失关键的时间或空间关系时采用，并提供海报、说明和降级内容。

“看起来更高级”不是升级媒介的理由。

## 组件边界

- **共享组件**承载稳定的阅读模式，例如术语解释、比较器、参数滑块、步骤演示、引用与媒体框。
- **领域组件**承载一类知识的共同模型，例如神经网络张量流、训练曲线或产品决策矩阵。
- **文章组件**只服务一个论证。将其放在文章附近，局部化 CSS 和脚本；出现第二个真实用例后再抽象。
- Astro 默认静态渲染。只有需要状态、输入、拖拽或连续动画时才使用客户端脚本；不要把整篇文章水合成单页应用。
- MDX 正文只放 import、调用和可读参数；图形运算、长数据、样式与脚本归组件。新增组件不能成为交付文章的主要进度指标。
- 交互状态不应成为正文唯一来源。关键结论同时存在于可索引、可复制的 HTML 中。

## AI 生成媒体的交付契约

生成图片、动图或 3D 资产前，先写清它证明什么，而不是只写风格提示词。每个资产至少记录：

- 教学目的与所在章节；
- 尺寸、比例和移动端裁切方式；
- 替代文本与必要的图注；
- 生成、拍摄或引用来源；
- 文件格式与体积控制；
- 失败时的静态替代物。

装饰性插图可以建立气氛，但不能冒充证据。技术结构、数值比例和界面状态必须由可校验的数据或代码生成，不能让图像模型自行猜测。

## 阅读体验

- 暖白编辑风是视觉底层，不强迫所有文章同构。每篇文章可以有自己的重点色和图形语言，但正文宽度、字号、间距和交互反馈保持稳定。
- 动效默认克制，不抢滚动、不自动播放带声音媒体、不制造无法跳过的开场。
- 图片、图表、代码和组件都要回答正文已经提出的问题；上下文没有引用的视觉对象应删除或换位置。
- 先完成可阅读的内容骨架，再添加表现层。视觉设计不能掩盖章节主线尚未成立。
- 核心机制需要完整解释正文，不以“骨架”或若干 lead 段代替。加入图后检查：原有推导、假设和边界是否仍然存在，读图解释是否经过实际观察。
