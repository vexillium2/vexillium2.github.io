# MDX 写作与实现

MDX 是创作源，Astro 管布局与构建，HTML 是发布结果。当前工程为 `astro-site/`。遵循现有路由和组织，不因改一篇文章迁移全站或引入 CMS。

- 段落、标题、列表、表格、图片和代码块用 Markdown。
- 数学用 `$...$`、`$$...$$`，就近解释符号；不用 JavaScript 字符串、行内代码或截图代替。
- 页面信息放 frontmatter，正文不重复硬编码页头。
- 图片可用 `![说明](/images/example.webp)`；需要尺寸、图注和视频控制时用小组件或适合 MDX 的元素。
- 组件显式 import 后调用；正文保留可读参数，长数据与业务逻辑移到组件或数据文件。
- 布局管排版，组件管局部样式与脚本。避免复制长 CSS、手写整套标题 DOM 或把正文放进大数组。
- MDX 含 JSX 语法，花括号、尖括号与属性需要正确处理。代码放 fenced block，用实际构建检查，不能默认只改后缀即可。

Astro 组件可用原生元素、CSS 或组件内脚本交互。React/Vue 等框架组件需要水合时，再按现有集成使用 `client:visible` 等指令；不对 `.astro` 组件机械加水合指令。

新增交互先让正文具备完整解释，再接入小组件；观察器、滑块和图形不能替换已批准的公式、步骤与边界。

格式迁移先检查内容等价及公式、表格、代码、图片兼容，再在明确范围内改写。保留源稿可恢复版本，记录新增和纠错；不用重新生成全文完成纯格式转换。

说明对照的内容基线：旧 Markdown 与 Astro v0.3 内容已不同，复制旧 Markdown 得到的 MDX 不能称为 v0.3 等价转换。

当前样例使用 `@astrojs/mdx`、Unified、remark-math、rehype-katex；检查配置与依赖确定实际管线。变化时查询对应版本官方文档。

构建后检查数学节点、渲染错误、局部滚动、字体与背景。数学正确性按学习性规则另验。
