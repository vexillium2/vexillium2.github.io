# 内容工作流与持久记录

用于新写、长文扩写、重构和迁移。Harness 控制输入、写作批次、验证证据与反馈；更多提示词条款本身不构成质量保证。

## 工作记录

较大改稿在 `.agents/handoffs/` 使用一份文章记录；按需要填写，不生成空报告。正文中不放工作流状态。

```markdown
# 文章写作记录
当前阶段：样节 / 分节写作 / 整合 / 待审核
正文路径：...
基线：源文件与本轮开始时的版本标识或摘要
已批准：大纲、样节位置、用户反馈及适用范围
读者目标：已有知识、读完能完成的任务、本篇核心与 recap
当前修改节：...
下一动作：...
未解决：位置、问题、所需证据或决定

## 知识去向
| ID | 原文位置与实际知识 | 动作 | 目标位置 | 验证/状态 |
| ... | 结论、推导、条件、例子 | 保留/改写/合并/移动/删除 | 文件与标题 | 对照情况 |

## 证据与验证
| 主张/样例/图片 | 来源与定位 | 类型与范围 | 验证结果/限制 |

## 读者审校与反馈
| 正文位置 | 卡住的具体问题 | 修改 | 复查结果 |
```

基线含未提交内容时，以工作区实际文件为准，不能只与 Git HEAD 比。保留可恢复版本，避免覆盖无关改动。

## 盘点与覆盖

识别实际知识，不只抄标题。长段可能含定义、公式、假设、工程例子和例外，都要有去向。字数与标题计数只能提示异常。

合并时说明重复在哪里，保留不同条件、推导和有价值的不同视角。删除知识需要依据与授权。纠错记录改前主张、正确说法与依据。移动写实际目标，尚未写成标为待迁移；不能宣称已完整交付。

格式迁移可用脚本检查原文段落、公式、列表、图注按序保留；重写后逐知识块检查语义。脚本不能证明语义完整。

## 样节定标

挑能暴露写作难度的核心节，例如 LoRA 从更新矩阵到参数量和 rank 取舍。交付完整解释链，不用导言或漂亮组件作样节。

样节显示读者起点、符号引入、关键推导或机制、可复算例子、结果含义与适用边界。定标的是解释深度与节奏，不要求所有概念套同一模板。

把用户反馈转换为可执行判断，如“矩阵写明形状”“保留标量到向量的中间过程”“工程结论写条件”。保存认可的正文位置，不凭空宣称某章已认可。篇幅范围可作预估，不能作合格阈值。

## 分节写作

一批覆盖一个可连贯解释的机制或小节。输入包括该节目标、原文知识块、必要相邻节、认可样节、相关来源与术语；避免带入整站源码和无关历史。

先写正文与公式，再验证数值和代码。素材未取得就记录缺口，不为了结束本轮把剩余节压成摘要。文章可以千行以上，按批写入并整合即可。

每批执行学习性审校，修复具体断点后继续。通常由同一 agent 顺序切换作者、核验者和读者视角；独立 agent 的使用服从用户授权与工具政策，本 Skill 不自行授权委派。

## 全文整合

检查跨批次符号、术语、例子参数、定义与数据一致。允许有功能的解释性复述，去掉无功能重复；修复重复导言、结论提前、概念先用后定义。

反查知识去向表，明确已覆盖和待迁移项。原文件还在、标题出现过或链接指向空页，都不能计作已覆盖。

## 反馈闭环

区分事实错误、解释断点、阅读偏好、范围变更。定位问题并在原位置修复，不把聊天回答直接粘到文末。

审校以可定位缺口为结果，不用模型总分宣称优秀。自动校验通过且具体缺口修复后交付，真实阅读体验仍由用户校准。
