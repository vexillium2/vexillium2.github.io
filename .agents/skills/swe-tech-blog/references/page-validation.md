# 富页面验收规则

交付 MDX / Astro 页面前读取。分别记录内容、实现与阅读体验的结果，不用构建通过替代内容验收。

## 内容与事实

- 对照文章工作记录的知识去向表，逐项核实结论、推导、条件、例子与图注；列出待迁移项。仅标题一致或源稿留存不能证明完整。
- 按 `learning-review.md` 检查解释、复算和条件变化问题，给出具体缺口和修复结果。模型试读不等于用户已认可。
- 标题树仍服务于一条主线；移除组件后，文章的核心结论仍然可辨认。
- 事实、数字、版本和引用有可追溯来源；易过期信息标注时间或版本范围。
- 图片、图表和交互的状态与正文一致，没有为了视觉效果简化成错误模型。
- 私密工作数据、凭据、个人信息和未脱敏素材不进入仓库或构建产物。

## 构建与运行

- 核实编辑源是可读 Markdown/MDX；内容与 CSS、脚本分离，公式无需 JavaScript 字符串转义。
- 运行项目约定的格式化、类型检查与生产构建；Astro 项目至少完成 `astro check` 与 `astro build`。
- 检查 MDX 的加粗、花括号、尖括号、表格、代码块是否出现字面标记泄漏；检查数学节点与 KaTeX 错误，渲染成功后仍需单独核验公式。
- 检查浏览器控制台、失效资源、重复 ID、无效链接与明显的布局位移。
- JS 失败时，正文、标题、图注和关键结论仍然可见。
- 文章专用样式没有改变其他页面；共享组件至少在两个代表性页面上检查。

## 视觉与交互

- 至少检查桌面与窄屏视口，不出现横向溢出、文字遮挡或触控目标过小。
- 用键盘走完交互路径；焦点可见，控件有名称，状态变化不只依赖颜色。
- 图片有合适的替代文本；纯装饰图片使用空替代文本。图表在正文或图注中提供结论。
- 动画可暂停或停止，并尊重 `prefers-reduced-motion`；视频和 3D 有静态海报或降级视图。
- 输入参数有范围、单位、默认值和重置方式；错误状态告诉读者发生了什么。

## 性能与资产

- 首屏之外的重媒体延迟加载；避免为了一个小效果引入整套大型运行时。
- 图片按显示尺寸输出现代格式，保留必要的高分屏版本，不提交无损原始大图作为网页资产。
- 客户端岛只包住需要交互的最小范围；停止使用的实验依赖和资源应清理。

## 交付记录

在文章工作记录中保存内容覆盖、证据、核验结果、读者审校缺口和未解决项；在项目变更日志简记文章路径、组件、资产来源、命令与浏览器结果。准确标注交付阶段，样节和局部初稿不能称为完整成稿。
