# 技术笔记写作 Harness

目标：产出可供读者学习、复算、实践和持续修改的文章。AI 负责研究、写作、验证与实现；用户负责方向、阅读反馈与重要取舍。正文密度以用户认可的样节为基准，不以 HTML 行数、字数、公式数或组件数判断质量。

## 任务与范围

先判断本轮是回答问题、审计、规划、新写、扩写、重构、载体迁移还是组件实现。回答与审计本身不授权重写；已经明确授权的修改应直接推进。

- **学习笔记**：优先建立概念、推导和可迁移理解，核心机制充分展开。
- **工程文章**：解释决策条件、实际行为、证据和代价。
- **载体迁移**：默认保持正文、知识范围和章节顺序，格式变化不授权压缩。
- **局部扩写**：读目标节及前后依赖；全文重构读完整正文、图片及相关笔记。

区分本篇核心、相邻笔记的必要 recap、拟移动材料。篇幅长不是删减、拆篇或降为 recap 的充分理由。移动内容必须有明确去向与状态；“留到未来”不能计作已完成迁移。

用户明确要求的大纲审批应遵守；既定大纲、样节和授权可跨轮复用。不要让用户重复审批来源、每个例子或例行技术选择。改变主题、删除知识或改变受众时再请求方向。

## 按任务读取

- 新写、扩写、重构与迁移：读 [内容工作流](references/writing-harness.md)。
- 推导、样例、图片解释、实践经验与内容审校：读 [学习性审校](references/learning-review.md)。
- MDX、布局与组件：读 [MDX 写作约定](references/mdx-authoring.md)。
- 图片、动画与交互设计：读 [富媒体设计](references/rich-page-design.md)。
- 页面交付：读 [页面验收](references/page-validation.md)。

纯数学证明有 `theory-notes` 时，可使用其记号、条件与证明检查；本 Skill 已覆盖普通 ML 工程笔记的公式解释。AI 可以提出教学顺序、构造并验证样例，不要求用户先提供全部逻辑。跨 Skill 有冲突时执行用户当前要求并记录实质冲突。

## 协作方式

长文按“知识盘点 → 代表样节 → 分节写作与验证 → 全文整合 → 富媒体与页面验收”推进。阶段是工作顺序，不是逐步停下询问的审批流。

选含核心公式或机制的样节校准深度。用户尚未认可这种写法时，先交付足够判断质量的完整样节；已有认可样节时按其标准继续。批准标题树不等于批准正文密度。内部按节写入文件，用户可以一次审核整篇，不要求每节回复“继续”。

较大改稿将目标、知识去向与未解决问题记到对应 handoff 文件；纯问答或小修无需新建记录。中断后从文件状态恢复。交付时准确说明是样节、部分章节、完整初稿还是已审核文章。

## 写作约束

- 正文用 Markdown/MDX，LaTeX 就地书写，样式归布局，脚本归组件；改一句话无需编辑 CSS 或 JavaScript。
- 背景、定义、机制、例子与边界按概念需要安排，用连续段落解释因果，不机械套块标签或为凑结构加章节。
- 标题标明技术对象与具体问题，便于查阅；避免夸张比喻和空泛反问。层级、章节数量与篇幅服从学习任务。
- 在读者需要处补定义、推导过渡和解释性复述。删去后仍能保持语法连贯，不代表可以删去。
- 同一技术使用一致术语，常用英文首次标注，正文优先中文。数学记号使用 LaTeX，不用行内代码代替数学排版。
- 核心机制让读者能解释为什么、何时失效；相邻知识做 recap 时给出实际可用的笔记链接。
- 表格服务共同维度比较，代码服务行为验证，图形服务结构或动态理解。不得用卡片、表格或图片压缩原有解释。
- 区分真实案例、报告结果、教学构造和未验证假设。没有经历材料，不写第一人称踩坑；自拟例子说明假设并验证。
- 时效事实核对原始来源并限定版本或时间；稳定原理依赖教材或原论文。按主张风险取证，不机械要求每句有两个来源。
- 来源、数值验证与素材出处放工作记录，正文引用形式服从用户要求，不强行加资料、面试或商业章节。
- 正文面向读者，不混入提示词、改稿争论、Skill 说明与实现教程，除非文章主题就是这些。

## 交付底线

内容覆盖、技术正确、解释可跟随、实现可用分别验收。构建成功只证明实现的一部分；模型自评能发现候选问题，不能证明读者已经理解。

交付前修复本轮范围内的具体缺口，并说明尚未解决的问题及位置。不能把原 Markdown 仍保留、所有标题仍在当作完整迁移证明。用户指出删薄时，核查知识块与推导链，不用补字数或增加组件应付。
